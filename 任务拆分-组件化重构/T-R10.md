# 组件化重构-T10 · data_missing 检测与提示机制

## 目标
数据缺失的检测与提示机制：透明降级的体验层落地（区别于行情数据门禁的失败语义）。

## 核心交付
1. **缺失检测**：按 DatasetSpec 验证联动声明（T-R5）逐数据集检测新鲜度/完整性
2. **提示通道**：检测结果结构化输出（web 黄条提示位消费；引擎C unavailable 灰条同语义）
3. **不阻断语义**：缺失→提示可见，评估流程**不得失败**（与 data_risk 门禁的显式区别，登记入文档）

## DoD 验收
- [x] 缺失场景实测：提示可见、流程不失败、结果标注 unavailable/降级
- [x] 检测与 spec 声明联动：新增数据集零代码接入检测
- [x] 单测覆盖：正常 / 缺失 / 新鲜但 incomplete 三分支

## 实施记录（2026-10-12）
- **实现单点**：`applib/datasets/__init__.py` `check_data_missing(ctx=None, repo=None, specs=None, stale_days=7, today=None)`
  - 驱动源：DatasetSpec.validation 声明（`required_keys` / `min_rows` / `as_of_field`）——新增数据集只写声明即自动接入（零代码）
  - 检测项：文件存在性（missing）→ JSON 解析（invalid）→ required_keys / min_rows（incomplete）→ as_of_field 新鲜度（stale）
  - severity 单值：missing(4) > invalid(3) > incomplete(2) > stale(1) > ok(0)，单数据集只返回最严重 status + reason
  - 模板路径支持：`trade_calendar_{mkt}.json` glob 任一命中即视为有数据
  - 返回结构：`{checked_at, stale_days, datasets: {id: {status, checks, reason?}}, summary, semantics}`，semantics 字段自描述"提示不阻断（透明降级）"语义
- **工具面入口**：`tools.py` 暴露 MCP 工具 `data.missing`（委托 check_data_missing，stale_days 可调）
- **不阻断语义**：检测全程不抛异常（全量缺失也返回结构化结果）；与 data_risk 门禁失败语义显式区别（semantics 字段 + 文档登记）；web 黄条 / 引擎C unavailable 灰条同语义消费
- **实施中修复 3 处实现缺陷**（单测先行发现）：
  1. `checks` 同语句自引用 UnboundLocalError → 拆分赋值
  2. `max(key=…)` 误返回 check key 而非 severity 名 → 先映射 severity 再取 max
  3. missing/invalid 提前 return 分支缺 `reason` 字段 → 补齐（提示可见性）
