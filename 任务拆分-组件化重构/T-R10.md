# 组件化重构-T10 · data_missing 检测与提示机制

## 目标
数据缺失的检测与提示机制：透明降级的体验层落地（区别于行情数据门禁的失败语义）。

## 核心交付
1. **缺失检测**：按 DatasetSpec 验证联动声明（T-R5）逐数据集检测新鲜度/完整性
2. **提示通道**：检测结果结构化输出（web 黄条提示位消费；引擎C unavailable 灰条同语义）
3. **不阻断语义**：缺失→提示可见，评估流程**不得失败**（与 data_risk 门禁的显式区别，登记入文档）

## DoD 验收
- [ ] 缺失场景实测：提示可见、流程不失败、结果标注 unavailable/降级
- [ ] 检测与 spec 声明联动：新增数据集零代码接入检测
- [ ] 单测覆盖：正常 / 缺失 / 新鲜但 incomplete 三分支

## 红线
提示不阻断（透明降级红线）；检测逻辑单点（不得在引擎内各自实现缺失判断）。
